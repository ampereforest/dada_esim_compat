# Preserved roadmap and selective-cleanup policy

## PhysicalSlot0 support

Preserving `0:0:0` while physical0 is absent does not validate a real pSIM1. Keep
the exact original modem/framework sources and read-only baselines for future work:

1. Obtain separately authorized, identifier-redacted pSIM1-present observations:
   full map/card-port/readiness/current registration, ordinary call/SIM-lock behavior.
2. Keep R2 PhysicalSim1Admission **positive classification** and unknown-context
   denial. Do not broaden logical1 bypasses or change pSIM1 when choosing pSIM2/eSIM.
3. Validate route/LPA concurrency and OEM/internal writer boundaries with explicit
   approval; current local gate is not global vendor quiescence.
4. Introduce no reset selector, automatic modem replay, NV/property routing store,
   guessed early SET or profile mutation as a shortcut.

## Native Settings integration

The protected3418/provider route UI remains the working interface. Original TeleService
shares OEM signing/sharedUID identity; its master-switch flow can disable profiles
before GPIO and ignore failures. A framework setter fence cannot make that app flow
safe. Preserve original APK/signature and native/framework bridge sources/toolchains.

Future work must authenticate the exact Settings→TeleService ingress, preserve
context/card/port/version across all wizard/Manage hops, quarantine profile-destructive
paths **before** side effects and retain consent/call/SIM/lock gates and result handling.
Use legitimately compatible signing if changing an OEM sharedUID APK; there is no
signature exemption or OEM private key here. Do not advertise the roadmap as completed.

## Independent acceptance gaps

- Corrected permanent init/CIL reflash on the exact V6 baseline, genuine unrooted
  handoff/switching/restart and enforcing merged-policy/socket labels.
- Neverallow/system-vendor boundary compliance and legitimate OEM AVB authentication.
- Broader ART/profile/VDEX-only/old data-cache replacement closure; no global cache wipe.
- Robust current-subscription voice+data registration, crash attribution and real
  call/data-transfer acceptance across route/profile changes.
- PhysicalSlot0-present tests and native OEM UI semantics; activation/download and
  contention/death/last-disable tests require separate approval.

## Cleanup: approval required, no deletions performed

Publication never authorizes deleting local workspace files. Measure candidates
with lstat/allocated bytes, inode identity and mounted backing-file checks before
asking for **specific** approval. Never delete a mounted image/backing workspace.

Potential candidates are only reproducible **generated** intermediate class/DEX
outputs, duplicate scratch disassemblies, discarded compression images and selected
attempt-local cache copies. Keep source/config/scripts and compact failure receipts
before any approved retirement; do not equate an old name with disposable evidence.

Strictly preserve:

- Base ROM archives/images, original extracted partitions/JARs/APKs/signatures and
  complete metadata/content manifests, authoritative LP geometry/prefix and UUID/time.
- Accepted corrected final ROM images, hashes and complete final verification, rejected
  flags3 bytes and historical failure/outcome receipts.
- OpenEUICC build tree, source changes and private signing keystore/password/cert identity.
- Native/owner/framework bridge/R1/R3 sources, genuine contracts, pinned V5/ART/NDK/JDK/
  SDK/toolchains and existing POSIX workspace scripts/ownership records.
- Active mounted backing files and immutable captures needed for physicalSlot0 routing
  and native Settings work. Detaching/retiring any workspace is separate authorization.

Private cleanup inventory and raw text audit remain **local-only**, never GitHub content.
